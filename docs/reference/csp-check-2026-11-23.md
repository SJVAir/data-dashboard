# CSP check: the built app on the local stack (2026-11-23)

The pre-go-live CSP check from step 6 spec 2 (`docs/superpowers/specs/2026-11-23-step-6-spec-2-csp-check-design.md`).
One walk (`e2e/csp-walk.ts`) opens every route and lazy part of the app and fails on any
Content Security Policy violation. It runs two ways: in the E2E suite on the fakes (CI), and
against the local stack's real header with `npm run test:csp-stack`.

**Result: no violations.** On the stack, Chromium, Firefox and WebKit each passed all 17 steps
with 0 violations.

## What was checked

- **Build:** `step-6-spec-2` at 8da07aa (buildId `8da07aa4015445f519dbd8163d87473d7fea92af`), put
  onto the stack's `/workspace/` by the coordinator. Built with `VITE_MAPTILER_KEY` and
  `VITE_NREL_KEY`, so the Map's tiles, glyphs and sprites really load, and with no Sentry DSN.
- **Header:** the enforced `Content-Security-Policy` (not Report-Only), with `default-src 'none'`
  and no `unsafe-eval` (the spec asserts both).
- **How violations were seen:** the stack has no report URI, so the walk collects them in the
  browser: a `securitypolicyviolation` listener installed before any page script, the console, and
  on Chromium the workers over CDP Audits.
- **Run:** 2026-11-23 22:36 PT, `npm run test:csp-stack`. Chromium and Firefox both passed, 17
  steps each, 0 violations: dashboard-list, new-from-starter, fullscreen, notes-editor,
  dashboard-dialogs, menu-dialogs, share-link, import-page, shared-page, data-portal-new,
  data-portal-edit, csv-download, open-in-chart, data-page, show-in, trimmed-paths,
  sign-out-dialog.
- **WebKit:** 2026-11-24 09:50 PT, `npm run test:csp-stack:webkit` in the Playwright image
  (`podman run --network host`, since WebKit won't start on this machine), against the same
  build: 17 steps, 0 violations, no skipped choices.
- **Skipped choices:** run 3 logged no skipped Show as choices on either engine (the Data Portal
  step skips and logs a choice it can't select).
- **Writes:** only the login and the walk's own `/api/2.0/documents/` requests. Each run leaves
  its dashboards in the local test account.

## On the fakes (CI)

The same walk runs under the contract CSP in the E2E suite. `e2e-full` was green on all three
engines at 32b9916 (run 45335567832). At 8da07aa (run 45341571319) Chromium and Firefox passed, and WebKit failed one place-picker
test that also fails on `step-6`: the closing picker's screen-reader region and the toast both
matched a page-wide text lookup. It was a test fix only (0811f11), with no CSP violation.

The worker self-test differs by engine: Chromium catches a worker's violation over CDP, Firefox
through the console, and WebKit can't (the test is `test.fixme`; see `DEFERRED.md`, "WebKit's
worker CSP violations aren't seen by the check").

Swap the final build into the stack, then run this from `data-dashboard`, outside :40–:50:

```bash
WORKSPACE_E2E_IDENTIFIER=… WORKSPACE_E2E_PASSWORD=… npm run test:csp-stack
```

The variables go right before the command and are never stored.
