This is a brand new SJVAir project. This will be a data dashboard for exploring and comparing the different data sets within the SJVAir ecosystem. I'd like to discuss and plan as much as possible before we start writing code. Currently, I've been using the latest versions of Svelte, sv-router, tailwind css, leveraging @sveltejs/enhanced-img for images, shadcn-svelte, typescript, vite, and @lucide/svelte for icons, date-fns for handling dates, uplot for charts, and @maptiler/sdk for maps (although we already have an interactive map located at ../monitor-map which should be preferred unless it makes more sense to build a new one, ideally the pre-existing one should be built in a way which it can be customized and embedded into other projects of ours. This may not be the case, as currently it is only used to build an interactive map, and be embedded into a capacitor.js app - the latest version being located at ../v3-mobile - so we may need to make updates to that project as well. Similarly, we might need to make updates to the ../sdk-js project for any interactions with the sjvair.com api. The server is located at ../sjvair.com for reference. We might need to update that projects openapi integration at some point to fill in missing data types.).

The first version of this should just be for exploring data. All initial design ideas are up for debate. A consistent goal throughout this project will be accessibility, we want the dashboard to be easy and intuitive for the everyday person to use. Maybe we can start with tabs for each data type available in the @sjvair/sdk (../sdk-sj).  Most of our data (if not all) is sorted by date, so corresponding data tabs should have a date range selector. Where it makes sense, data tabs should offer multiple ways of viewing data (e.g. spreadsheet, map, charts/graphs), and these should be able to be toggled on or off. I think a lot can be determined though the monitor meta data, but we can check that out when we get to it. I'm pretty sure that the server has county information, so maybe we can have data available by date range, and location (although I don't think we have this functionality in the sdk yet, so we might have to update that project first - if that's the case, we can just put that on the roadmap for now). I'd like to have a global "settings" or "preferences" which keeps track of the selections and preferences of a user (date ranges in tabs, which data views are enabled - e.g. spreadsheet, map). Initially, these setting will just be saved to local storage, but the goal is to someday have them loaded from the server (this will be a listed feature in the ROADMAP.md). URL parameters should be used also, so that a user can share the url with another person, and that second person can load the same state which the first person was looking at (same data type and selected parameters, but not preferences).

Features on the roadmap will be a unified "Data Analysis" tab which will allow users to select multiple data sets they want to view for analysis. This "Data Analysis" tab should include common tools and analysis methods used in data science (ideally using web assembly for any heavy computational work, although there should be existing web assembly libraries for use to utilize rather than making one ourselves). We want to compare data and look for trends. Also, one thing to keep in mind as we plan this and develop it, is that I would like to make this a desktop app with Tauri at some point, and offer extended capabilities which are not possible (or just not worth the cost) in the browser.

I'd like your help refining the plans for this project. Creating the CLAUDE.md, ARCHITECTURE.md, ROADMAP.md, and another file for tracking TODO items and keeping track of where we left off in our overall plan and what/where to continue developing.
